    Parameters¶

    One frozen dataclass per parameter set, flat, the way Rust sees it. Grouped by the module that takes them; Shared goes to more than one.

    Shared¶

    Parameter bundles for the single cell suite.

    One frozen dataclass per parameter bundle, flat as Rust sees them: ScrubletParams(no_pcs=10, k=0) rather than nested blocks. Field names, defaults and ranges are generated from the parameter specs. ScenicParams is written by hand, see bixverse.params._scenic.

    min_width float

    Wrapper function for parameters for neighbour identification in single cell

    Attributes:

    Name Type Description
    knn_sym Literal['snn', 'umap', 'knn']

    How to symmetrise the kNN into a graph. Clustering resolutions do not carry over between the methods: the "umap" and "knn" graphs only hold kNN pairs, the sNN graph also links cells that share neighbours and prunes weak edges. The same resolution can give more or fewer communities depending on the data, so retune it when switching.
    snn_similarity Literal['jaccard', 'rank']

    "snn" only. "jaccard" weighs an edge by the Jaccard index of the two (self-inclusive) neighbour sets. "rank" takes the shared neighbour with the lowest combined rank, so closer shared neighbours give heavier edges. Both are scaled to [0, 1].
    pruning float

    "snn" only. Edges below this weight are dropped.     Wrapper function for parameters for NEBULA

    Parameters for the NEBULA negative binomial gamma mixed model, implemented in Rust via the edge-rs crate and ported from the nebula package's own C++. Defaults follow the nebula package. NEBULA splits the variance into a subject- level random effect and a cell-level overdispersion. Run it on meta cells and the cell-level term becomes the spread between aggregates within a subject rather than between cells, so it is smaller and absorbs whatever the aggregation smoothed away. The subject-level term keeps its meaning either way.

    max_sigma float

    Upper bound on the subject-level overdispersion.

    Wrapper function for parameters for AUCell

    The three statistics consume the same within-cell ranking, but weight it very differently. "wilcox" is a pure function of the gene set's rank sum, so a gene at rank 2 and one at rank 200 count for almost the same thing. "recovery" and "ap" are top-heavy. For SCENIC use "recovery", the default. "wilcox" is a bixverse addition and its flatter score does not separate into on/off populations, so it binarises badly. Ranking ties are averaged (midranks) rather than broken at random the way AUCell does it, which is why there is no need for SCENIC's trick of setting the cutoff to the 1st percentile of genes detected per cell. Undetected genes all collapse onto one rank well outside any sensible max_rank. Note the recovery AUC is normalised by max_rank * length(gene_set), matching pySCENIC and AUCell's normAUC = False. Modern AUCell divides by the attainable maximum instead, so absolute values differ by a per-gene-set constant. Cell ordering within a regulon is unaffected.

"recovery" is the recovery-curve AUC under a rank cutoff, i.e. the actual AUCell statistic of Aibar, et al. "ap" is average precision, the most top-heavy of the three, but its null tracks the gene set prevalence so raw values are not comparable across gene sets of different size unless standardise is on.

    *,

    snn_similarity: Literal["jaccard", "rank"] = "jaccard",

    Helper function to generate the kNN graph defaults

    Controls how a kNN is turned into the undirected, weighted graph that the clustering runs on. "snn" is the shared nearest neighbour graph of bluster/Seurat, "umap" the fuzzy simplicial set ScanPy builds (its obsp/connectivities) and "knn" the plain kNN union. Each method only reads its own parameters.

    Attributes:

    Name Type Description
    knn_sym Literal['snn', 'umap', 'knn']

    How to symmetrise the kNN into a graph. Clustering resolutions do not carry over between the methods: the "umap" and "knn" graphs only hold kNN pairs, the sNN graph also links cells that share neighbours and prunes weak edges. The same resolution can give more or fewer communities depending on the data, so retune it when switching.
    snn_similarity Literal['jaccard', 'rank']

    "snn" only. "jaccard" weighs an edge by the Jaccard index of the two (self-inclusive) neighbour sets. "rank" takes the shared neighbour with the lowest combined rank, so closer shared neighbours give heavier edges. Both are scaled to [0, 1].
    pruning float

    "snn" only. Edges below this weight are dropped. For the Jaccard weight a threshold p keeps pairs that share at least a fraction 2p / (1 + p) of their (self-inclusive) neighbourhoods, rounded up to whole cells, so the same value means the same thing at any k. The default asks for about 12%, i.e. 2 of 16 shared cells at k = 15, in line with Seurat's 1/15. Avoid a threshold that equals one of the discrete weights exactly, or float rounding decides whether the edge survives.
    rescue bool

    "snn" only. Reconnect the small components that pruning cuts off via their strongest sNN edge, so they do not turn up as tiny clusters.
    local_connectivity float

    "umap" only. Number of nearest neighbours assumed to be fully connected, as in umap-learn.
    mix_ratio float

    "umap" only. 1 is the fuzzy union of the directed kNN memberships, 0 the fuzzy intersection (umap-learn's set_op_mix_ratio).
    binary bool

    "knn" only. If True, every edge weighs 1. Otherwise mutual neighbours weigh 2 and one-sided ones 1.
