    Input and output¶

    Getting counts into an experiment directory, and back out.

    Every loader takes the directory to create and returns the opened SingleCells. Pick the one for your format: load_csr for counts already in memory, load_h5ad, load_tenx_h5 or load_mtx for files, and the load_multi_* twins for several files in one go. After the first load you only need load_existing.

    What a load does. It applies the cell and gene QC of MinQualityParams (by default at least 100 genes, 250 counts per cell and 10 cells per gene), so dropped cells and genes never enter the store. It then writes the cell-major and gene-major stores and loads obs and var into the DuckDB, adding nnz and lib_size to obs and no_cells_exp to var. Loading into a directory that already holds an experiment overwrites its stores and drops any saved memory_py.*.

    Several files. prescan_h5ad_files, prescan_tenx_h5_files and prescan_mtx_dirs read the gene sets first and fix the gene universe (intersection by default, or union), then load_multi_* loads against that prescan. obs gains exp_id and cell_id is prefixed with it. To combine experiments you already loaded, merge_sc_experiments keeps the shared genes and each input's kept cells, and carries no cache over.

    Saving. obs and var edits go to the DuckDB at once. save writes what lives in memory: the cell filter, the HVG set and the cache, as memory_py.npz and memory_py.json. It does not write a fitted residual model, and warns. load_existing brings it all back, and restores the stores from counts.bxa if only the archive is left (archive_sc_exp). save_h5ad exports kept cells, obs, var and the embeddings and graph that still match to an h5ad file; write_h5ad_sc, write_tenx_h5_sc and write_cellranger_output write in-memory counts as files other tools read.

    Test data. generate_single_cell_test_data plants cell types in synthetic counts. The generate_* twins serve the ADT, CellSweep and DIALOGUE examples. The download_* functions fetch the vignette data sets into ~/.cache/bixverse and return the path, or the cached one.

    params = bv.params.SyntheticDataParams(n_cells=2000, n_genes=500)
sim = bv.io.generate_single_cell_test_data(params, seed=1)
sc = bv.io.load_csr("experiments/demo", sim.counts, sim.obs, sim.var)

bv.pp.find_hvg(sc, hvg_no=200)
bv.io.save(sc)
sc = bv.io.load_existing("experiments/demo")

    Gotchas. The loaders want integral raw counts. load_h5ad finds them with detect_raw_count_slot, which prefers layers.counts, then raw.X, then X; set raw_count_slot if it picks wrong, and use load_h5ad_norm for files that only hold log-normalised values. load_mtx takes genes as rows, the 10x convention, unless cells_as_rows says otherwise; get_cell_ranger_params finds the three files for you. Nothing here needs h5py. A store in the old v3 format still opens with a warning, and upgrade_sc_store converts it.

    Worked through in Single-cell data I/O in bixverse and Scaling to millions of cells with bixverse.

    load_csr ¶

    load_csr(

    obs: DataFrame,
    var: DataFrame,
    *,
    qc: MinQualityParams | None = None,
    csc_mem_gb: float | None = None,
    verbose: Verbose = True,
) -> SingleCells

    Load an in-memory cells x genes count matrix.

    obs and var go in with every column name snake_cased, the first column renamed to cell_id / gene_id (obs names then made unique), only the rows that survive QC.

    Parameters:

    Name Type Description Default
    directory Path | str

    The experiment directory, created if missing.

    		 required
    counts CsrLike

    Cells x genes CSR matrix of integral counts.

    		 required
    obs DataFrame

    One row per matrix row, identifier first.

    		 required
    var DataFrame

    One row per matrix column, identifier first.

    		 required
    qc MinQualityParams | None

    Cell and gene QC thresholds and the target size.

    		 None
    csc_mem_gb float | None

    Memory in GB for the CSR to CSC conversion buffers. None converts in one pass.

    		 None
    verbose Verbose

    0 (False) silent, 1 (True) progress, 2 extra detail where the method has it.

    		 True

    Returns:

    Type Description
    SingleCells

    The experiment.

    Raises:

    Type Description
    ValueError

    If obs / var do not match the matrix or the counts are not integral.

    Examples:

    >>> sc = bv.io.load_csr("experiments/demo", sim.counts, sim.obs, sim.var)
>>> qc = bv.params.MinQualityParams(min_lib_size=500)
>>> sc = bv.io.load_csr("experiments/lax", sim.counts, sim.obs, sim.var, qc=qc)

    Looking at a file first¶

    Getting counts into an experiment directory, and back out.

    Every loader takes the directory to create and returns the opened SingleCells. Pick the one for your format: load_csr for counts already in memory, load_h5ad, load_tenx_h5 or load_mtx for files, and the load_multi_* twins for several files in one go. After the first load you only need load_existing.

    What a load does. It applies the cell and gene QC of MinQualityParams (by default at least 100 genes, 250 counts per cell and 10 cells per gene), so dropped cells and genes never enter the store. It then writes the cell-major and gene-major stores and loads obs and var into the DuckDB, adding nnz and lib_size to obs and no_cells_exp to var. Loading into a directory that already holds an experiment overwrites its stores and drops any saved memory_py.*.

    Several files. prescan_h5ad_files, prescan_tenx_h5_files and prescan_mtx_dirs read the gene sets first and fix the gene universe (intersection by default, or union), then load_multi_* loads against that prescan. obs gains exp_id and cell_id is prefixed with it. To combine experiments you already loaded, merge_sc_experiments keeps the shared genes and each input's kept cells, and carries no cache over.

    Saving. obs and var edits go to the DuckDB at once. save writes what lives in memory: the cell filter, the HVG set and the cache, as memory_py.npz and memory_py.json. It does not write a fitted residual model, and warns. load_existing brings it all back, and restores the stores from counts.bxa if only the archive is left (archive_sc_exp). save_h5ad exports kept cells, obs, var and the embeddings and graph that still match to an h5ad file; write_h5ad_sc, write_tenx_h5_sc and write_cellranger_output write in-memory counts as files other tools read.

    Test data. generate_single_cell_test_data plants cell types in synthetic counts. The generate_* twins serve the ADT, CellSweep and DIALOGUE examples. The download_* functions fetch the vignette data sets into ~/.cache/bixverse and return the path, or the cached one.

sim = bv.io.generate_single_cell_test_data(params, seed=1)

bv.pp.find_hvg(sc, hvg_no=200)
bv.io.save(sc)
sc = bv.io.load_existing("experiments/demo")

    Gotchas. The loaders want integral raw counts. load_h5ad finds them with detect_raw_count_slot, which prefers layers.counts, then raw.X, then X; set raw_count_slot if it picks wrong, and use load_h5ad_norm for files that only hold log-normalised values. load_mtx takes genes as rows, the 10x convention, unless cells_as_rows says otherwise; get_cell_ranger_params finds the three files for you. Nothing here needs h5py. A store in the old v3 format still opens with a warning, and upgrade_sc_store converts it.

    Store maintenance¶

    Getting counts into an experiment directory, and back out.

    Every loader takes the directory to create and returns the opened SingleCells. Pick the one for your format: load_csr for counts already in memory, load_h5ad, load_tenx_h5 or load_mtx for files, and the load_multi_* twins for several files in one go. After the first load you only need load_existing.

    What a load does. It applies the cell and gene QC of MinQualityParams (by default at least 100 genes, 250 counts per cell and 10 cells per gene), so dropped cells and genes never enter the store. It then writes the cell-major and gene-major stores and loads obs and var into the DuckDB, adding nnz and lib_size to obs and no_cells_exp to var. Loading into a directory that already holds an experiment overwrites its stores and drops any saved memory_py.*.

    Several files. prescan_h5ad_files, prescan_tenx_h5_files and prescan_mtx_dirs read the gene sets first and fix the gene universe (intersection by default, or union), then load_multi_* loads against that prescan. obs gains exp_id and cell_id is prefixed with it. To combine experiments you already loaded, merge_sc_experiments keeps the shared genes and each input's kept cells, and carries no cache over.

    Saving. obs and var edits go to the DuckDB at once. save writes what lives in memory: the cell filter, the HVG set and the cache, as memory_py.npz and memory_py.json. It does not write a fitted residual model, and warns. load_existing brings it all back, and restores the stores from counts.bxa if only the archive is left (archive_sc_exp). save_h5ad exports kept cells, obs, var and the embeddings and graph that still match to an h5ad file; write_h5ad_sc, write_tenx_h5_sc and write_cellranger_output write in-memory counts as files other tools read.

    Test data. generate_single_cell_test_data plants cell types in synthetic counts. The generate_* twins serve the ADT, CellSweep and DIALOGUE examples. The download_* functions fetch the vignette data sets into ~/.cache/bixverse and return the path, or the cached one.
