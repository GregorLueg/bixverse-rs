    Batch correction¶

    Batch correction and integration metrics.

    Pick a correction, then check it. harmony (v2) and harmony_v1 (the original) correct the cached PCA. fast_mnn, seurat_cca and seurat_rpca work from the counts of the batch-aware HVGs, so run bv.pp.find_hvg_batch_aware first and hand them its hvg_gene_idx. bbknn skips the embedding and builds a batch-balanced kNN instead. The calculate_* functions score the result, and calculate_integration_metrics runs the lot and returns one row.

    What lands where. Harmony, fastMNN, CCA and rPCA write a corrected embedding to sc.cache.embeddings under "harmony", "harmony_v1", "mnn", "cca" and "rpca". bbknn writes sc.cache.knn and sc.cache.connectivities, replacing what is there. All are stamped. The metrics return records (or a table) and leave the experiment alone. Everything takes a SingleCells or SingleCellsSubset except seurat_cca and seurat_rpca, which want a SingleCells. The batch labels are an obs column named by batch_column; its levels are sorted, an Enum keeps its own order.

    bv.pp.find_hvg(sc, hvg_no=2000)
bv.pp.calculate_pca(sc, no_pcs=30)
bv.integrate.harmony(sc, "batch_index")
bv.graph.find_neighbours(sc, embd_to_use="harmony")
metrics = bv.integrate.calculate_integration_metrics(
    sc, "batch_index", cell_type_column="cell_grp", embd_to_use="harmony"
)

    Gotchas. The kNN metrics (calculate_kbet, calculate_lisi, calculate_graph_connectivity) read the cached kNN, so rebuild the neighbours on the corrected embedding before scoring it; on a stale kNN they warn, on one that covers other cells they raise. The silhouette widths are O(n^2) and subsample to max_cells (5000). calculate_pcr compares a corrected embedding with the PCA, so it needs both. For bbknn there is no embedding: pass embd_to_use=None to calculate_integration_metrics, and the metrics that need one come back null. A single batch warns and returns without doing anything, bar fast_mnn, which raises. seurat_cca and seurat_rpca with use_precomputed_pca=True still need the gene loadings, so they save less than fastMNN does.

    Worked through in Batch correction with bixverse.

    		 5
    embd_to_use Literal['pca']

    The embedding; only "pca".

    		 'pca'
    no_embd_to_use int | None

    Number of leading dimensions to use. None for all.

    bbknn_params BbknnParams | None

    The parameters. None uses the defaults.

    calculate_integration_metrics ¶

    calculate_integration_metrics(
    sc: ScOrScSubset,
    batch_column: str,
    *,
    cell_type_column: str | None = None,
    embd_to_use: str | None = "pca",
    max_cells: int | None = 5000,
    seed: int = 42,
    verbose: Verbose = True,
) -> DataFrame

    The batch mixing and biological conservation metrics in one row.

    Every column is on [0, 1] (the PCR comparison can go negative), higher is better: kbet_accept (1 - rejection rate), batch_asw (mean(1 - |s|)), ilisi, pcr_comparison, clisi, cell_type_asw and graph_connectivity. The kNN metrics read the cached kNN, so rebuild the neighbours on the corrected embedding first. A metric that cannot run (no kNN, no embedding, embd_to_use=None as for BBKNN, no cell_type_column) is null.

    Parameters:

    Name Type Description Default
    sc ScOrScSubset

    The experiment.

    		 required
    batch_column str

    obs column with the batch.

    		 required
    cell_type_column str | None

    obs column with the cell types; None skips the conservation metrics.

    		 None
    embd_to_use str | None

    The embedding for the silhouettes and the PCR; None skips them.

    		 'pca'
    max_cells int | None

    Subsampling for the silhouette widths.

    		 5000
    seed int

    Seed for the subsampling.

    		 42
    verbose Verbose

    0 (False) silent, 1 (True) progress, 2 extra detail where the method has it.

    		 True

    Returns:

    Type Description
    DataFrame

    One row: embedding, kbet_accept, batch_asw, ilisi,
    DataFrame

    pcr_comparison, clisi, cell_type_asw, graph_connectivity.

... )

    Biological conservation¶

    Batch correction and integration metrics.

    Pick a correction, then check it. harmony (v2) and harmony_v1 (the original) correct the cached PCA. fast_mnn, seurat_cca and seurat_rpca work from the counts of the batch-aware HVGs, so run bv.pp.find_hvg_batch_aware first and hand them its hvg_gene_idx. bbknn skips the embedding and builds a batch-balanced kNN instead. The calculate_* functions score the result, and calculate_integration_metrics runs the lot and returns one row.

    What lands where. Harmony, fastMNN, CCA and rPCA write a corrected embedding to sc.cache.embeddings under "harmony", "harmony_v1", "mnn", "cca" and "rpca". bbknn writes sc.cache.knn and sc.cache.connectivities, replacing what is there. All are stamped. The metrics return records (or a table) and leave the experiment alone. Everything takes a SingleCells or SingleCellsSubset except seurat_cca and seurat_rpca, which want a SingleCells. The batch labels are an obs column named by batch_column; its levels are sorted, an Enum keeps its own order.

    bv.pp.find_hvg(sc, hvg_no=2000)
bv.pp.calculate_pca(sc, no_pcs=30)
bv.integrate.harmony(sc, "batch_index")
bv.graph.find_neighbours(sc, embd_to_use="harmony")
metrics = bv.integrate.calculate_integration_metrics(
    sc, "batch_index", cell_type_column="cell_grp", embd_to_use="harmony"
)

    Gotchas. The kNN metrics (calculate_kbet, calculate_lisi, calculate_graph_connectivity) read the cached kNN, so rebuild the neighbours on the corrected embedding before scoring it; on a stale kNN they warn, on one that covers other cells they raise. The silhouette widths are O(n^2) and subsample to max_cells (5000). calculate_pcr compares a corrected embedding with the PCA, so it needs both. For bbknn there is no embedding: pass embd_to_use=None to calculate_integration_metrics, and the metrics that need one come back null. A single batch warns and returns without doing anything, bar fast_mnn, which raises. seurat_cca and seurat_rpca with use_precomputed_pca=True still need the gene loadings, so they save less than fastMNN does.
