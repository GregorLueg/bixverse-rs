    Doublet detection with bixverse¶

    Python port of the R vignette Doublet detection with bixverse. Original author: Gregor Lueg.

    Intro¶

    Doublets, droplets containing two or more cells, are a common artefact in droplet-based single cell experiments. If left undetected, they masquerade as intermediate cell states or novel populations and quietly corrupt downstream analyses. This vignette demonstrates three doublet detection approaches available in bixverse and benchmarks them against ground truth calls from demuxlet, which identifies doublets via genetic variation across pooled donors.

    bixverse provides three computational doublet detection methods:

    • Scrublet is a simulation-based approach (Wolock, et al., 2019). It generates synthetic doublets by averaging pairs of randomly selected cells, embeds both real and synthetic cells together, and scores each real cell by the proportion of its nearest neighbours that are synthetic. A bimodal score distribution is expected: singlets cluster near zero, doublets near one. A threshold on this score determines the final calls.

    • Boosted doublet detection takes a different angle. Rather than scoring against the neighbours, it repeatedly simulates doublets, clusters real and synthetic cells together and flags clusters enriched for synthetic doublets. A cell is called a doublet if enough iterations vote for it. This can be more robust when the score distribution from Scrublet is not cleanly bimodal, though it introduces its own hyperparameters (and is substantially slower).

    • scDblFinder is a port of the scDblFinder method from Germain et al., with one modification: it uses lightGBM with the histogram trick on the feature space instead of xgboost, which tends to be faster to fit. It trains a classifier on real versus synthetic doublets and combines the classifier output with cxds co-expression scores (Bais and Kostka) into a weighted final score. Across published benchmarks it tends to be the strongest of the three.

    All three methods are purely computational and work without genetic or hashing information. They complement experimental approaches like demuxlet, which require pooled donors or hashtag antibodies. They also have a failure mode if a large number of doublets dominates the original data.

def doublet_metrics(predicted: pl.Series, actual: pl.Series) -> dict[str, float]:
    pred = predicted.to_numpy()
    act = (actual == "DBL").to_numpy()
    tp = np.sum(pred & act)
    fp = np.sum(pred & ~act)
    fn = np.sum(~pred & act)
    precision = tp / (tp + fp)
    recall = tp / (tp + fn)
    f1 = 2 * (precision * recall) / (precision + recall)
    return {
        "precision": round(float(precision), 4),
        "recall": round(float(recall), 4),
        "f1": round(float(f1), 4),
    }

    Running with grouping variables or within specific cell subsets¶

    Scrublet (and the other methods) have two parameters if you wish to run the detection method within a specific set of cells (cells_to_use=None) and/or want to use a grouping variable, like running the doublet detection within individual samples (group_by=None).

    Boosted doublet detection¶

    The boosted approach repeatedly simulates doublets and clusters them together with the real cells. This can work better when the Scrublet score distribution is messy or unimodal. However, by default it runs 20 iterations of the algorithm, which means 20x generation of synthetic doublets. The initial PCA is kept for subsequent reprojection; nonetheless, this makes it slower than the other methods in this vignette.

    Overall, it takes longer and has worse performance (in this data set). If you wish to have a partially orthogonal method, it can be worthwhile nonetheless. There is also an option to accelerate the algorithm via fast clustering. This runs k-means clustering with sqrt(n_cells) * 4 centroids by default, the kNN on these centroids, Louvain on the smaller kNN graph and projects the Louvain membership back for final scoring. This comes at a cost of recall, as you can see below. You need to check how many centroids you need to represent your data properly. On smaller data sets, you can get away with n_cells / 10 and compress 10 cells into one centroid... On larger data sets, you might want to compress further.

    Should you observe that the cxds scores are very flat or you only have a few data points (this can occur in low complexity experiments in which the highest expressing genes are VERY similar across all the cells, for example in cell culture experiments), you can bump cxds_genes up. The default here is 500, but you might want to increase this pending your experiment.

    PCA solver and HVG method¶

    All three methods run their own PCA on the observed and simulated cells. You pick the solver via svd_solver. The default here is "randomised", a randomised SVD that is approximate in the trailing components. "covariance" builds the gene x gene cross-product over the HVGs and eigendecomposes it, which is exact, but the doublet methods run on more genes and that matrix grows with the square of the gene count, so it gets painfully slow here. "auto" (the default in PcaParams) runs Lanczos on the sparse path and the covariance solver on the dense one. "exact" runs Lanczos on the sparse path and a full SVD on the dense one. Scrublet and the boosted method also take the HVG method via hvg_method, including the scran trend:

    ScrubletParams(
    expected_doublet_rate=0.12,
    hvg_method="scran",
    svd_solver="covariance",
)

    Conclusion¶

    All methods can help to identify doublets in your data in a data-driven way. In a later re-evaluation by Xi and Li, scDblFinder came out on top across different benchmark data sets, see Germain et al., 2021. Here it has the highest recall and the lowest precision of the five runs. Which one wins on this data set is in the metrics above.
